# 명함 읽기 시험 (이슈 127 · D-84)

앱 **설정 → 실험 → 명함 읽기 시험** 과 짝을 이루는 도구. 앱 코드가 아니다. 느린 부자의 캡처 읽기 시험(`Tools/ocr-sim`)을 본떴다.

## 앱에서

1. `명함 사진 고르기` — 사진첩에서 명함 사진을 20장까지. 같은 명함을 세 방식으로 읽는다.
   ① 앱과 같은 길(테두리를 찾아 편 사진 · 고쳐 읽기 끔) ② 펴지 않은 원본 ③ ①에 고쳐 읽기(언어 보정) 켬.
2. 칸(이름 · 소속 · 직무 · 휴대전화 · 사무실 · 팩스 · 이메일)마다 **맞는 값을 누른다.** 셋이 다 틀렸으면 `모두 틀림`,
   읽은 것이 없고 명함에도 그 칸이 없으면 `읽은 것 없음 — 명함에도 없음`.
3. 맨 위 표에 방식별 · 칸별 `맞음 / 채점한 칸` 이 모인다. 아무것도 저장하지 않는다 — 화면을 나가면 사라진다.
4. 틀린 명함은 `읽은 결과 복사 → 가리고 복사` 로 대화에 붙여 넣는다. 숫자 `#` · 영문 `x` · 한글 `○` 로 가리고,
   직무 · 회사 · 연락 이름표 낱말만 남긴다(`Packages/Core/Sources/Core/Cards/CardMasking.swift`).

## 여기서

```
python3 Tools/card-reading/from_paste.py 붙여넣은.txt [--lines]
```

붙여 넣은 글의 방식마다 읽은 줄로 규칙(`Tools/golden/generate.py` 의 `parse_card`)을 다시 돌려 칸을 찍는다.
앱이 낸 값과 다르면 표시한다. 규칙을 고친 뒤 같은 글로 다시 돌려 무엇이 바뀌는지 본다.

**받은 글은 저장소에 넣지 않는다** — 실제 사람의 명함이다. 고칠 거리는 모양만 본떠 지어낸 사례로 `Tools/golden/cases.json` 의 `cardParse` 에 더한다.

## 무엇을 보나

| 방식이 갈리는 곳 | 뜻 |
|---|---|
| ①만 틀리고 ②가 맞음 | 테두리 찾기 · 펴기가 글자를 망쳤다(기울기 · 잘림) |
| ①만 틀리고 ③이 맞음 | 고쳐 읽기를 켜는 편이 낫다(영문 · 낯익은 낱말) |
| 셋 다 같은 값으로 틀림 | 글자는 읽혔고 **규칙**(이름 · 직무 · 소속 가르기)이 틀렸다 — `from_paste.py --lines` 로 줄을 본다 |
| 셋 다 못 읽음 | 글자 인식 자체 — 세로 명함 · 작은 글씨 · 장식 글꼴 |
