# 느린 인연 (Slow Ties)

## 1. 한눈에
- 한 줄 소개 (30자 안팎): 연락처가 아니라, 사람과 쌓은 인연을 적는 앱
- 누구를 위한 앱인가 (한두 줄): 업무와 일상에서 만난 사람을 "어떻게 알게 되었고 무엇을 함께했는지"로 기억하고 싶은 사람. 지금(테스트 기간) 실제 사용자는 만든 사람 1명이다.
- 만든 까닭 — 어떤 불편에서 시작했나 (두세 줄): 보통의 연락처 앱은 이름·전화·메일·소속을 모으는 데서 끝난다. 정작 중요한 건 누구와 어떤 계기로 인연을 맺었고 함께 무엇을 했는가인데, 그걸 남겨 둘 곳이 없었다.

## 3. 핵심 기능 (실제로 되는 것만)
- 사람과 첫 인연 — 이름 하나로 시작하고, 처음 만난 날·알게 된 경로·소개해 준 사람·첫 인연 메모를 천천히 채운다.
- 함께한 기록 — 대화·식사·회의 같은 기록을 여러 사람과 함께 한 번만 적으면, 모두의 타임라인에 나타난다. 기록마다 시각과 사진 4장까지. 앞날짜로 적은 약속은 홈의 다가오는 만남에 보이고, 그날이 지나면 결과를 적도록 챙긴다(1.1).
- 명함과 연락처 — 명함을 찍으면 기기 안에서 글자를 읽어 이름·소속·연락처를 제안하고, 고르는 건 사람이 한다. 연락처에서 골라 가져올 수도 있다.
- 내 인맥 — 관계도·모임 찾기·해마다 달라진 모임(시점 막대 · D-59)로 내 인맥의 모양을 본다. 모임마다 다른 색, 사람이 많아도 이름이 보인다(1.1.2). 한 해 돌아보기로 해마다 함께한 사람 · 처음 만난 사람 · 달마다 기록을 본다(1.1.1 ~ 1.1.4). 사람에게 점수나 순위를 매기지 않는다.
- 찾기와 정리 — 초성으로 찾고, 관계 유형·태그로 거르고, 태그 이름을 바꾸거나 합친다. 처음 만난 날·기록 날짜는 월까지·연도만으로도 적는다.
- 사진 · 잠금 · 내보내기 — 사람 사진, 앱 잠금(Face ID · 기기 암호), 한 사람을 Markdown · PDF 로 내보내기, 지운 뒤 5초 안에 되돌리기.
- 동기화와 알림 — 같은 Apple 계정의 아이폰·아이패드가 iCloud 로 같은 자료를 보고(기본 켬), 생일·알게 된 지 n주년·연락 주기·만난 뒤 결과 적기 알림을 기기 안에서 건다(알림은 기본 꺼짐). 1.1.7 에서 결혼기념일 · 입사일 같은 기념일을 여러 개 적고 기념일마다 · 사람마다 알림을 켜고 끈다. 아이패드에서는 왼쪽 바 · 목록 · 상세로 나눠 본다.

## 4. 원칙 점검
- 계정(회원가입) 없이 쓴다: 예 — 처리방침에 "회원가입이 없습니다".
- 광고가 없다: 예 — 광고 도구가 없고, 앱이 하는 통신은 iCloud 동기화 하나뿐이다(저장소 규칙 · 코드).
- 추적 · 분석 도구가 없다: 예 — 처리방침에 "사용 기록·분석·광고 식별자를 수집하지 않습니다", 저장소 규칙이 분석·추적 도구를 금지.
- 서버가 없다 (자료가 개발자에게 가지 않는다): 예 — 개발자 서버가 없고, 처리방침에 "개발자는 볼 수도 꺼낼 수도 없습니다".
- 자료가 사용자의 기기 · 사용자의 iCloud 에만 있다: 예 — 기기 안, 그리고 동기화를 켜면 본인 iCloud 의 비공개 영역(설정에서 끌 수 있음).
- 앱을 지워도 자료가 남는다 (파일로 남는가): 조건부 예 — 기기 안 자료는 앱과 함께 지워진다. 설정의 백업 파일(.json)·vCard 로 내보내 두면 파일로 남고, iCloud 동기화를 켜 두었으면 iCloud 에도 남는다.

## 5. 만든 이력
- 만들기 시작한 날 · 첫 출시까지 걸린 기간: 2026-10-17 시작(첫 커밋 · 요구사항 검토). 같은 날 밤 첫 TestFlight 빌드, 2026-10-18 부터 실사용. 첫 출시 2026-11-01 — 시작부터 16일.
- 낸 판 수 · 테스트 빌드 수: App Store 에 출시한 판 7 (1.0 · 1.1.2 · 1.1.4 · 1.1.6 · 1.1.7 · 1.1.9 · 1.1.10) — 심사 대기 중에 더 나은 판이 나오면 앞 판을 빼고 새 판으로 냈다(1.1 · 1.1.1 · 1.1.3 · 1.1.5 · 1.1.8 은 출시하지 않음). TestFlight 빌드 60 (2026-11-05 · 빌드 번호 = 배포 워크플로 실행 번호). 2026-10-17 ~ 11-05 커밋 약 400개(작업 브랜치 · CI 스크린샷 커밋 포함). (2026-11-05 갱신) 1.0 때: 테스트 빌드는 배포 워크플로 37번 실행(빌드 번호 = 실행 번호 · 2026-10-22 기준 28개는 설정 검증 1번 · 실패 2번 제외). 2026-10-17~31 커밋 257개(작업 브랜치).
- 사용자 피드백으로 고친 이야기:
  - 연락처를 가져오면 휴대전화·사무실·팩스·메일이 한 칸에 뭉쳐 들어왔다. → 연락 수단을 다섯 칸으로 나누고, 연락처의 이름표와 명함의 `M.` `T.` `F.` `E.` 표시로 갈라 넣게 했다.
  - 관계도 아래 시점 막대를 옮기면 그림이 커졌다 작아졌다 했고, 사람이 늘수록 이름끼리 겹쳤다. → 시점과 상관없이 그림 칸 높이를 고정하고 새 자리로 부드럽게 옮겨 가게 했으며, 이름은 서로 겹치지 않는 자리에만 쓰게 했다.
  - 큰 아이폰에서 기록을 고치다 가로로 돌리자 편집 창이 닫혀 적던 것이 사라졌다(1.1.3). → 큰 아이폰은 돌려도 화면 뼈대를 바꾸지 않고, 아이패드는 입력 중에는 뼈대를 붙잡게 했다. CI 가 가장 큰 아이폰 시뮬레이터에서 돌려 보는 시험을 더했다.
  - 날짜를 고를 때 해를 바꾸는 순간 달력이 닫혀, 해 · 달 · 날을 고를 때마다 다시 열어야 했다(1.1.6). → 해 → 달 → 날 차례로 고르고 날을 눌러야 닫히는 달력으로 바꿨다.
  - 아이패드를 잠가 둔 밤사이 앱이 꺼졌다. → 크래시 로그로 원인(잠긴 동안 동기화로 깨어나 보호된 파일을 읽음)을 찾아, 저장 파일 보호 등급을 바꾸고 잠긴 동안에는 화면 쪽 계산을 미루게 했다.
- 다른 느린 앱에서 배워 이 앱에 쓴 것: 맥 없이 GitHub Actions 로 빌드·테스트·배포하는 방식과 파이썬 정답표로 계산을 검증하는 방식(느린 부자·느린 여백). 삭제 전 확인과 지운 항목을 다시 그리지 않는 규칙, iCloud 저장 형태를 CI 로 올리는 방식(느린 부자). 사진첩에서 사진을 고르는 방식(느린 여백 — 이 앱에서 사진을 고르면 꺼지던 문제를 그 방식으로 고침).
