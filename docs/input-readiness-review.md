# 입력 상태 · 준비도 검토

> 사용자 (2026-10-18): *지금의 입력 상태를 지표화해서 유의미한 결과가 나오기 위해서 필요한 인원, 속성 등에 대한 가이드를 주는 것도 큰 도움이 될 것 같아. 종합적으로 검토해서 사용자들이 잘 사용할 수 있게 도움이 되는 앱을 만들어보자.*

**한 줄.** 앱이 알려 줄 수 있는 것은 전부 **입력**에서 나온다. 그러니 "내 입력이 지금 어디까지 왔고, **무엇을 얼마나 더 적으면 무엇이 보이는지**" 를 한 곳에서 보여 주고, 빈 곳을 바로 채우러 가게 한다.

**원칙과의 관계 (ADR-0004).** 점수를 매기는 대상은 **사람이 아니라 내 입력**이다. 사람마다 "완성도 점수" 를 붙이거나 줄 세우지 않는다. 사람 이름이 나오는 곳은 **채울 것 목록**(빈 칸이 있는 사람)뿐이고, 이름 순이다.

## 1. 기능마다 필요한 입력 — 지금 앱에 있는 것 전부

| 기능 | 무엇을 보여 주나 | 필요한 입력 | 뜻을 갖는 최소 조건 (제안) |
|---|---|---|---|
| 사람 목록 · 검색 | 사람 찾기 | 이름 | 1명 |
| 관계 돌아보기 (사람마다) | 기록 수 · 마지막 기록 · 인연 기간 · 빈도 · 흐름 · 함께한 일 | 그 사람과의 **기록**(날짜 · 유형), 처음 만난 날 | 빈도 · 함께한 일 3건, 흐름 4건 (요구사항 5.5) |
| 돌아보기 — 최근 기록 없음 | 오래 기록이 없는 사람 | 사람마다 기록 1건 이상 | 기록이 있는 사람 **절반 이상** |
| 돌아보기 — 올해 처음 만남 | 올해 알게 된 사람 | **처음 만난 날** | 처음 만난 날을 적은 사람 **절반 이상** |
| 특성 — 관계 유형 · 알게 된 경로 · 소속 · 태그 | 내 인연의 구성 | 그 칸 | 그 칸을 적은 사람 **80% 이상**, 사람 **20명 이상** |
| 관계도 | 사람끼리의 연결 | **함께한 사람이 2명 이상인 기록**, 소개 | 서로 이어진 사람 **30% 이상** |
| 그룹 찾기 (빌드 10) | 모임 · 묶음 | 위 + **아는 사이 잇기** | 진한 선 **20개 이상** · 이어진 사람 **10명 이상** |
| 시점에 따른 변화 (그다음) | 묶음이 어떻게 변했나 | 기록 **날짜**가 여러 분기에 걸침 | 기록이 **2개 분기 이상**, 분기마다 진한 선 10개 |

> 조건의 숫자는 제안이다. 원칙 4("기록이 모자라면 지표 대신 안내")를 기능 전체로 넓힌 것이다. 숫자는 Core 한 곳(`InputReadiness`)에 두고 정답표로 대조한다.

## 2. 입력 상태 지표 — 무엇을 셀까

| 지표 | 정의 | 왜 |
|---|---|---|
| 사람 | 나를 뺀 사람 수 | 분포 · 그룹의 바탕 |
| 처음 만난 날을 적은 비율 | 처음 만난 날 있음 ÷ 사람 | 올해 처음 만남 · 인연 기간 · 시점 변화 |
| 관계 유형을 적은 비율 | | 특성 분포 · 관계도 칩 |
| 알게 된 경로를 적은 비율 | | 특성 분포 |
| 소속을 적은 비율 | | 특성 분포 · 그룹 이름 |
| 기록이 있는 사람 비율 | 기록 1건 이상 ÷ 사람 | 돌아보기 전반 |
| 돌아보기가 열린 사람 | 기록 3건 이상인 사람 수 | 관계 돌아보기의 빈도 · 함께한 일 |
| 함께한 기록 비율 | 함께한 사람이 2명 이상인 기록 ÷ 기록 | 관계도의 선 |
| 서로 이어진 사람 비율 | 진한 선이 하나라도 있는 사람 ÷ 사람 | 관계도 · 그룹 |
| 기록이 걸친 분기 수 | 기록 날짜가 걸친 분기 | 시점 변화 |

종합 점수 하나로 묶지 **않는다** — 무엇을 하면 좋아지는지가 묻힌다. 기능마다 `준비됨 · 거의 · 아직` 세 단계와 막대(지금 / 조건)로 보인다.

## 3. 화면 — 어디에 어떻게

**`입력 상태` 칸** (제안: 내 인맥의 첫 칸, 또는 목록 맨 위 나 칸 아래 한 줄)

```
입력 상태                                    [자세히]
관계도        ███████░░░  서로 이어진 사람 21% / 30%   거의
특성 분포     ██████████  관계 유형 92% · 사람 34명      준비됨
올해 처음 만남 ███░░░░░░░  처음 만난 날 28% / 50%       아직
돌아보기      ████░░░░░░  기록 3건 이상 4명              아직
```

**`자세히`** — 기능마다 무엇을 하면 좋아지는지와 **채울 것 목록**:

| 채울 것 | 누르면 |
|---|---|
| 처음 만난 날이 빈 사람 23명 | 이름 순 목록 → 사람을 누르면 **바로 편집** |
| 관계 유형이 빈 사람 3명 | 〃 |
| 아직 기록이 없는 사람 18명 | 〃 → 기록 추가 |
| 함께한 사람이 한 명뿐인 기록 41건 | 기록 목록 → 기록 수정(함께한 사람 더하기) |

- 목록은 **이름 순** — 누가 더 "모자란" 사람인지 줄 세우지 않는다.
- 하루 10명 입력 흐름에 맞춰, `저장하고 다음 사람 추가` 배너에 **오늘 채운 것** 한 줄을 더할 수 있다: `오늘 13명 · 처음 만난 날 9명 · 함께한 기록 2건`.
- 문구는 늘 "무엇을 더 적으면 무엇이 보이는지" 꼴로 — `처음 만난 날을 12명 더 적으면 올해 처음 만남이 보입니다`.

## 4. 만들기 — 어디에 무엇을

- Core `InputReadiness` — 위 지표와 조건 판정(준비됨 · 거의 · 아직), 다음 할 일 문구. 정답표 사례: 빈 저장소, 절반 채움, 다 채움, 경계값.
- 앱 — 인맥 자료(`NetworkSnapshot`)를 만들 때 함께 센다(이미 따로 연 문맥에서 사람 · 기록을 한 번 돈다). 주 스레드를 막지 않는다.
- 채울 것 목록에서 바로 편집 — 기존 `PersonEditView` · `RecordEditView` 시트를 연다.

## 5. 정할 것

1. `입력 상태` 를 어디에 둘까 — 내 인맥 첫 칸 / 목록 맨 위(나 아래) 한 줄 / 둘 다?
2. 조건 숫자(특성 80% · 사람 20명 · 연결 30% · 처음 만난 날 50% …)를 이대로 시작할까?
3. 채울 것 목록에서 사람을 누르면 **바로 편집**을 열까, 상세로 갈까?
4. 언제 넣을까 — 빌드 10 (아는 사이 잇기 · 그룹 찾기와 함께)?
