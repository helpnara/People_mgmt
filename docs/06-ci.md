# CI · TestFlight 절차 — 맥 없이 내 폰까지

느린 여백 `docs/06-ci.md` · 느린 부자 `docs/06-testflight.md` 를 이 앱에 맞게 줄였다. 두 앱과 **같은 팀 · 같은 API 키**를 쓴다.

## 1. 워크플로 다섯 개

| 파일 | 언제 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| `core-test.yml` | `Packages/Core/**` · `Tools/golden/**` · 개인정보 명세 푸시 | ① ubuntu: 파이썬 정답표가 최신인가 · 명세 검사 ② `swift:6.1-noble`: `swift build` + `swift test` | 2~4분 |
| `ios.yml` | `docs/**` · `*.md` · 스크린샷 · 정답표 · 사이트 도구 **말고** 모든 푸시 | macOS: XcodeGen → Core 테스트 → 빌드 → 앱 테스트 → 스크린샷(iPhone 8장 · 다크 2 · iPad 2) → 화소 검사 → 아티팩트 → `screenshots/` 커밋 | 20~30분 (스크린샷이 대부분) |
| `testflight.yml` | **수동** — 사용자가 "착수하자" 할 때만 | 아카이브 · 서명 · 검증 · 업로드 | 5~7분 + 애플 처리 10~30분 |
| `site.yml` | `docs/privacy.md` 변경 | GitHub Pages 에 처리방침 한 장 | 1분 |
| `probe.yml` | 수동 | macOS 러너에서 명령 하나 | 1분 |

문서만 고친 푸시는 `ios.yml` 이 건너뛴다 (`paths-ignore`).

## 2. 처음 한 번 — 사용자가 해야 하는 것

### 2.1 GitHub — 기본 브랜치 · 시크릿 · 변수 · Pages

| 할 일 | 어디서 | 값 |
|---|---|---|
| **기본 브랜치를 `main` 으로** | 저장소 Settings → General → Default branch | `main` (제가 `master` 와 같은 내용으로 만들어 올렸다). 수동 실행 전용 워크플로(`testflight.yml` · `probe.yml`)는 **기본 브랜치에 있어야** Actions 목록에 나타난다 |
| **시크릿 4개** | Settings → Secrets and variables → Actions → Secrets | `APPLE_TEAM_ID` · `APP_STORE_CONNECT_KEY_ID` · `APP_STORE_CONNECT_ISSUER_ID` · `APP_STORE_CONNECT_KEY_P8` — **느린 여백 · 느린 부자와 완전히 같은 값.** API 키는 팀 단위라 앱마다 만들지 않는다. 다만 시크릿은 쓰기 전용이라 다른 저장소에서 꺼내 올 수 없다 — 보관해 둔 `.p8` 원본이 필요하다 |
| **변수 1개** | 같은 화면 → Variables | `SUPPORT_EMAIL` = 지원 메일. 없으면 처리방침이 게시되지 않는다 (가짜 주소가 나가는 것보다 낫다) |
| **Pages** | Settings → Pages → Source | **GitHub Actions**. 주소는 `https://helpnara.github.io/People_mgmt/privacy/` |
| Pages 배포 브랜치 (선택) | Settings → Environments → `github-pages` → Deployment branches and tags | 기본은 **기본 브랜치(`main`)만** 배포가 허용된다. 2026-10-17 에 작업 브랜치에서 돌린 게시가 deploy 단계에서 단계 없이 1초 만에 실패한 이유다. 작업 브랜치에서도 바로 게시하려면 여기에 `claude/*` 를 더한다. 더하지 않으면 **처리방침은 `main` 에서만 게시된다** — 스토어에 낸 판과 같은 문서가 공개되므로 그대로 두어도 된다 |

> `.p8` 은 줄바꿈까지 그대로 넣는다. 한 줄로 붙으면 서명이 실패한다. 키 액세스는 **Admin** 이어야 한다 — App Manager 로는 서명 자산을 못 만든다 (`Cloud signing permission error`).

### 2.2 Apple 개발자 콘솔 — App ID

<https://developer.apple.com/account/resources/identifiers/list> → **+** → **App IDs** → **App**

| 항목 | 값 |
|---|---|
| Description | `Slow Connection` (콘솔의 Description 칸은 **한글을 받지 않는다**) |
| Bundle ID | **Explicit** 로 `com.helpnara.slow.connection` |
| Capabilities | **아무것도 켜지 않는다.** iCloud · 푸시를 쓰지 않는다. 동기화를 켜는 날 iCloud 를 더하고 컨테이너 `iCloud.com.helpnara.slow.connection` 을 만든다 |

기기는 지난 앱 때 등록해 두었으므로 다시 할 것이 없다 (자동 서명이 개발용 프로파일을 구우려면 팀에 기기가 하나는 있어야 한다).

### 2.3 App Store Connect — 앱 등록

<https://appstoreconnect.apple.com> → **앱** → **+** → **신규 앱**

| 항목 | 값 |
|---|---|
| 플랫폼 | iOS |
| 이름 | **느린 인연** — 이미 쓰이는 이름이면 거부된다. 그 자체가 가정 A1 의 검증이다 |
| 기본 언어 | 한국어 |
| 번들 ID | `com.helpnara.slow.connection` |
| SKU | `slowconnection` |

### 2.4 첫 배포

`Actions → TestFlight 배포 → Run workflow` → 브랜치 `claude/slow-connection` → 변경 사항에 아무거나 → Run. 초록이면 5~15분 뒤 TestFlight 에 `1.0 (실행 번호)` 로 보인다.
App Store Connect → 앱 → TestFlight → **내부 테스팅** 그룹에 본인 Apple ID. 수출 규정은 `ITSAppUsesNonExemptEncryption: false` 로 미리 답해 두었다.

## 3. 막다른 길 — 다시 시도하지 말 것 (지난 두 앱에서 확인)

| 시도 | 결과 |
|---|---|
| 수동 실행 전용 워크플로를 작업 브랜치에만 두고 실행 | **404.** 기본 브랜치에 있어야 GitHub 이 등록한다 |
| `CODE_SIGN_IDENTITY` 를 배포용으로 강제 | 자동 서명과 충돌로 거부 |
| `CODE_SIGNING_ALLOWED=NO` 로 아카이브 | 패키징이 건너뛰어져 자격이 앱에 안 박힌다 |
| `CODE_SIGN_IDENTITY=-` (애드혹) | SDK 가 거부 |
| `manageAppVersionAndBuildNumber` 를 안 끔 | Xcode 가 빌드 번호를 제멋대로 바꾼다 |
| 리눅스 세션에서 Swift 설치 | `download.swift.org` 가 막혀 있다 |

## 4. 자주 나는 오류

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `maximum number of certificates` | 러너가 매번 새 기계라 개발 인증서를 계속 발급 | developer.apple.com → Certificates 에서 오래된 **Apple Development** 폐기. 배포용은 건드리지 않는다 |
| `No profiles for 'com.helpnara.slow.connection' were found` | App ID 미등록 또는 번들 ID 오타 | §2.2 |
| `Cloud signing permission error` | API 키가 Admin 이 아니거나, ASC 계약에 미동의 | 키를 새로 만들거나 계약 확인 |
| `iOS 26.0 is not installed` | Xcode 를 다른 26.x 로 바꿨다 | 이미 26 이상이면 손대지 않는다 (워크플로가 그렇게 돼 있다) |
| 워크플로가 커밋을 못 함 (403) | 기본 토큰이 읽기 전용 | `permissions: contents: write` |
| 푸시 거부 (non-fast-forward) | CI 가 스크린샷을 커밋함 | `git pull --rebase` |
| `The Xcode build system has crashed` 가 같은 자리에서 두 번 | 소스 문자열 안의 곧은 따옴표 | 강조는 `**…**` 로 |

## 5. 원격 세션에서 미리 돌려 볼 수 있는 것

```bash
python3 -I Tools/golden/generate.py          # 정답표 다시 만들기
python3 -I Tools/golden/generate.py --check  # CI 와 같은 검사
python3 -I Tools/privacy/check-privacy-manifest.py
python3 -I Tools/site/build.py /tmp/_site --preview
python3 -I Tools/contrast.py                 # 글자 색 대비 4.5 (CI 와 같은 검사)
python3 Tools/make-icon.py                   # Tools/icon-source.png 를 1024 아이콘으로 굽기
```
