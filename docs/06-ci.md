# CI · TestFlight 절차 — 맥 없이 내 폰까지

느린 여백 `docs/06-ci.md` · 느린 부자 `docs/06-testflight.md` 를 이 앱에 맞게 줄였다. 두 앱과 **같은 팀 · 같은 API 키**를 쓴다.

## 1. 워크플로 여섯 개

| 파일 | 언제 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| `core-test.yml` | `Packages/Core/**` · `Tools/golden/**` · 개인정보 명세 · `Palette.swift` · `Tools/cloudkit/**` · `Schema.swift` 푸시 | ① ubuntu: 파이썬 정답표가 최신인가 · 개인정보 명세 검사 · 색 대비 검사(`Tools/contrast.py`) · CloudKit 스키마 파일이 최신인가(`generate-ckdb.py --check`) ② `swift:6.1-noble`: `swift build` + `swift test` | 2~4분 |

| `cloudkit-schema.yml` | 수동 | ubuntu: 모델 → 스키마 파일 → CloudKit **개발 환경**에 읽기 · 검사 · 적용 (§7) | 1분 |

## 2. 처음 한 번 — 사용자가 해야 하는 것

### 2.1 GitHub — 기본 브랜치 · 시크릿 · 변수 · Pages

| 할 일 | 어디서 | 값 |
|---|---|---|
| **기본 브랜치를 `main` 으로** | 저장소 Settings → General → Default branch | `main` (제가 `master` 와 같은 내용으로 만들어 올렸다). 수동 실행 전용 워크플로(`testflight.yml` · `probe.yml` · `cloudkit-schema.yml`)는 **기본 브랜치에 있어야** Actions 목록에 나타난다 — 새로 만들면 그 파일 하나만 `main` 에도 올린다(실행은 작업 브랜치 내용으로 돈다) |
| **시크릿 4개** | Settings → Secrets and variables → Actions → Secrets | `APPLE_TEAM_ID` · `APP_STORE_CONNECT_KEY_ID` · `APP_STORE_CONNECT_ISSUER_ID` · `APP_STORE_CONNECT_KEY_P8` — **느린 여백 · 느린 부자와 완전히 같은 값.** API 키는 팀 단위라 앱마다 만들지 않는다. 다만 시크릿은 쓰기 전용이라 다른 저장소에서 꺼내 올 수 없다 — 보관해 둔 `.p8` 원본이 필요하다 |
| **변수 1개** | 같은 화면 → Variables | `SUPPORT_EMAIL` = 지원 메일. 없으면 처리방침이 게시되지 않는다 (가짜 주소가 나가는 것보다 낫다) |
| **Pages** | Settings → Pages → Source | **GitHub Actions**. 주소는 `https://helpnara.github.io/People_mgmt/privacy/` |
| Pages 배포 브랜치 (선택) | Settings → Environments → `github-pages` → Deployment branches and tags | 기본은 **기본 브랜치(`main`)만** 배포가 허용된다. 2026-10-17 에 작업 브랜치에서 돌린 게시가 deploy 단계에서 단계 없이 1초 만에 실패한 이유다. 작업 브랜치에서도 바로 게시하려면 여기에 `claude/*` 를 더한다. 더하지 않으면 **처리방침은 `main` 에서만 게시된다** — 스토어에 낸 판과 같은 문서가 공개되므로 그대로 두어도 된다 |

> `.p8` 은 줄바꿈까지 그대로 넣는다. 한 줄로 붙으면 서명이 실패한다. 키 액세스는 **Admin** 이어야 한다 — App Manager 로는 서명 자산을 못 만든다 (`Cloud signing permission error`).

### 2.4 첫 배포

`Actions → TestFlight 배포 → Run workflow` → 브랜치 `claude/slow-connection` → 변경 사항에 아무거나 → Run. 초록이면 5~15분 뒤 TestFlight 에 `1.0 (실행 번호)` 로 보인다.

## 4. 자주 나는 오류

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `maximum number of certificates` | 러너가 매번 새 기계라 개발 인증서를 계속 발급 | developer.apple.com → Certificates 에서 오래된 **Apple Development** 폐기. 배포용은 건드리지 않는다 |
| `No profiles for 'com.helpnara.slow.connection' were found` | App ID 미등록 또는 번들 ID 오타 | §2.2 |
| `Cloud signing permission error` | API 키가 Admin 이 아니거나, ASC 계약에 미동의 | 키를 새로 만들거나 계약 확인 |
| `iOS 26.0 is not installed` | Xcode 를 다른 26.x 로 바꿨다 | 이미 26 이상이면 손대지 않는다 (워크플로가 그렇게 돼 있다) |
| 워크플로가 커밋을 못 함 (403) | 기본 토큰이 읽기 전용 | `permissions: contents: write` |
| 푸시 거부 (non-fast-forward) | CI 가 스크린샷을 커밋함 | `git pull --rebase` |
| `The Xcode build system has crashed` 가 같은 자리에서 두 번 | 소스 문자열 안의 곧은 따옴표 | 강조는 `**…**` 로 |

## 6. 실기기 크래시 로그 읽기

크래시 로그(설정 → 개인정보 보호 및 보안 → 분석 및 향상 → 분석 데이터)는 앱 안의 자리를 **주소**로만 준다.
`frames` 의 `imageIndex: 0` 이 앱이고 `imageOffset` 이 앱 안 위치다.

1. **빌드 5부터** — `testflight.yml` 이 `dsym-<빌드 번호>` 아티팩트로 기호 파일을 남긴다 (90일).
2. **탐침으로 바꾼다** — `probe.yml` 에서 아티팩트를 받아 `atos` 를 돌린다. 주소는 `0x100000000 + imageOffset`.
   ```
   gh run download <testflight 실행 id> -R helpnara/People_mgmt -n dsym-<번호> -D /tmp/d
   atos -arch arm64 -o /tmp/d/SlowConnection.app.dSYM/Contents/Resources/DWARF/SlowConnection -l 0x100000000 <주소들>
   ```
3. **기호 파일이 없는 빌드**(빌드 4 이전) — 그 빌드의 커밋을 탐침에서 `CODE_SIGNING_ALLOWED=NO CURRENT_PROJECT_VERSION=<번호>` 로
   다시 아카이브하면 **같은 UUID** 가 나온다 (빌드 4 에서 확인 — `dwarfdump --uuid` 로 크래시 로그의 `slice_uuid` 와 맞춰 본다).
   UUID 가 다르면 그 결과는 믿지 않는다.

**종료 코드 읽기.** `0x8BADF00D` = 주 스레드가 제때 답하지 않아 시스템이 끈 것(워치독) — 멈춘 자리는 주 스레드 맨 위 프레임들.
`JetsamEvent` 로그 = 메모리 초과. `EXC_BREAKPOINT` = Swift 의 강제 풀기 · 범위 밖 · `fatalError`.

## 7. iCloud 동기화 켜기 (D-42 · ADR-0005)

콘솔 Description 칸은 영문만 받는다.

1. **App ID 능력** — developer.apple.com → Certificates, Identifiers & Profiles → Identifiers → `com.helpnara.slow.connection` → Capabilities 에서 **iCloud** (Include CloudKit support) 와 **Push Notifications** 를 켠다 → Save.
2. **iCloud 컨테이너** — Identifiers 오른쪽 위 필터를 **iCloud Containers** 로 → `+` → Description `Slow Connection Data`, Identifier `iCloud.com.helpnara.slow.connection` → Register.
3. **App ID 에 컨테이너 잇기** — 다시 App ID → iCloud 옆 **Configure** (또는 Edit) → 방금 만든 컨테이너를 체크 → Continue → Save. 프로파일이 바뀐다는 확인이 나오면 Confirm.
4. **관리 토큰** — icloud.developer.apple.com → 오른쪽 위 계정 메뉴 → **Settings** → **Tokens** → **+ Create Management Token** (이름 `github-actions-slowconnection`) → 나온 값을 GitHub 저장소 Settings → Secrets and variables → Actions → **New repository secret** `CKTOOL_MGMT_TOKEN` 에 넣는다. 만료일을 `docs/08-feedback.md` 에 적는다. `APPLE_TEAM_ID` 는 이미 있다. **지금 토큰: 2026-10-19 발급 · 2027-10-19 만료** — 만료되어도 앱 · 동기화 · TestFlight 는 영향이 없고, 스키마를 다시 올릴 때만 막힌다(그때 새로 만들어 같은 이름의 시크릿을 Update).
5. **스키마를 개발 환경에** (원격 세션이 돌린다) — Actions → **CloudKit 스키마** → `action = read` 로 지금 상태를 본 뒤 `action = apply`, `allow_real` 체크. 스키마 파일은 `Tools/cloudkit/generate-ckdb.py` 가 `App/Persistence/Schema.swift` 의 지금 판에서 만든 `Tools/cloudkit/slowconnection.ckdb` (손으로 고치지 않는다 · `core-test.yml` 이 최신인지 검사).
6. **스키마 배포** (사람) — icloud.developer.apple.com → CloudKit Console → 컨테이너 `iCloud.com.helpnara.slow.connection` → **Schema** 에서 개발 환경에 `CD_Person` · `CD_Record` · `CD_Tie` · `CDMR` 이 보이는지 확인 → **Deploy Schema Changes…** → Production 으로 Deploy.
7. **동기화 판** — `CloudSync.mainStoreSyncAvailable = true` 로 바꾸고 TestFlight 로 올린다 (내보내기는 늘 Production). **빌드 21 에서 했다 (2026-10-19).**

**막다른 길** (빌드 20, 2026-10-19): 앱 안에서 `initializeCloudKitSchema()` 로 스키마를 만들려면 개발 환경에 붙은 판이 필요한데, App Store Connect 로 내보내는 판은 `iCloudContainerEnvironment = Development` 를 거부한다(`value Development is not allowed`). TestFlight 판은 늘 Production 이다 — 그래서 CI 의 CKTool JS 로 간다 (느린 부자와 같은 길).

스키마를 바꾸는 판마다(6판 빌드 28 · 7판 빌드 29 에서 했다) 5~6 을 되풀이한다 (`generate-ckdb.py` 로 파일을 다시 만들고 커밋 → apply → Deploy) — 배포 환경은 칸을 더하기만 된다.
