# 열린 이슈

형식: `번호 · 상태 · 제목 · (발견 빌드) · 내용` — 상태는 🔴 급함 · 🟡 고칠 것 · 🔵 알아볼 것 · 🟢 해결 · 🟠 뒤엎음(대신하는 항목 번호를 적는다).

**이슈는 사용자가 실기기 · 스크린샷에서 발견하고, 세션이 여기에 번호로 적는다.** 5개 내외 모이면 "착수할까요?" 를 묻는다.
자료 유실 · 저장 실패만 예외로 바로 고친다.

- **모임 찾기** (D-30) — Core `CommunityDetection`(Louvain · 고정 차례 · 연결 쪼개기) · `CommunityNaming`, 정답표 `louvain` · `splitConnected` · `communityName`. 진한 선만, 무게 = 함께한 기록 + 소개 1 + 아는 사이 1. 진한 선 20개 · 이어진 사람 10명 · 모듈성 0.3 이상일 때만, 3명 이상 묶음을 관계도에 옅은 테두리 · 이름 · 모임 칩으로. 점 번호는 이름 순으로 매겨 켤 때마다 같은 모임이 나온다.
- **입력 상태** (D-31) — Core `InputReadiness`, 정답표 `inputReadiness`. 목록 맨 위(나 아래) 한 줄 요약 + 내 인맥의 `입력 상태` 칸(기능마다 준비됨 · 거의 · 아직 · 막대 · 무엇을 더 적으면 무엇이 보이는지 · 채울 것 목록).
- 견본에 `-seedCommunitySample`(지어낸 15명 · 세 모임) — 파이썬 Louvain 으로 미리 돌려 모임 넷(모듈성 0.70)을 확인하고 스크린샷 21 로 찍는다. 입력 상태는 스크린샷 20.
- 이슈 15: 관계 미리 읽기 · 날 번호 산수 · 단계별 시간 로그(`인맥 · …`). CI 시간 로그로 무거운 단계를 보고 고친다.
